MQTT Modul¶

Az MQTT modul biztosítja a kapcsolatot az ESP32 és az MQTT broker között, lehetővé téve a parancsok fogadását, a hardveres állapotváltozások publikálását és a rendszer telemetria küldését.

Működés és MQTT Interfész¶

A modul figyeli a brokerkapcsolat állapotát, és rendszeresen telemetriai jelentést küld a kapcsolat megbízhatóságáról.

Publikációk¶

  • Topic: <topic>/telemetry
  • JSON Mezők:
    • name: Az eszköz konfigurált alap topicja (base topic).
    • mqtt_errors: Az MQTT csatlakozási hibák / megszakadások száma.

Példa üzenet:

{
  "name": "esp32_07",
  "mqtt_errors": 0
}

Beállítások¶

A webes konfigurációs felületen a következő MQTT paraméterek adhatók meg:

  • Aktív (Active): Kapcsoló az MQTT kliens engedélyezésére vagy tiltására.

  • Broker: Az MQTT broker IP-címe vagy tartományneve (hostname).

    Fontos figyelmeztetés biztonságos SSL használatakor

    Hitelesített SSL/TLS kapcsolat esetén a kliens nem fogad el közvetlen IP-címet a tanúsítvány ellenőrzésekor, még akkor sem, ha az IP-cím szerepel az alt_names mezőben az SSL kiterjesztési (.ext) konfigurációban! Kizárólag érvényes hosztnév megadása támogatott.

  • Port: Az MQTT broker portja (nem titkosított esetben tipikusan 1883, SSL esetén 8883).
  • SSL engedélyezése (SSL flag): Titkosított TLS kapcsolat használata.
  • Insecure SSL flag: Nem biztonságos SSL mód (a szerver tanúsítványának ellenőrzésének kihagyása).
  • Alap topic (Base topic): Az eszköz egyedi fő MQTT topicja. A modulok ezt használják alapértelmezésben a parancsok fogadására és állapotok küldésére (példa: esp32_01).
  • Közös alap topic (Common base topic): Közös topic előtag csoportos parancsokhoz. Bizonyos modulok (például az Audio és File storage modulok) erre is feliratkoznak a csoportos vezérlés érdekében (példa: esp32).
  • Kliens ID (Client ID): Egyedi azonosító a brokerhez való kapcsolódáskor (példa: Esp32_Client_01).
  • Felhasználó (Username): Felhasználónév a broker hitelesítéshez (opcionális).
  • Jelszó (Password): Jelszó a broker hitelesítéshez (opcionális).
  • Életben tartás (Keep Alive): Ping üzenetek gyakorisága másodpercben (alapértelmezett: 30 másodperc).
  • Puffer méret (Buffer size): MQTT csomagpuffer mérete bájtban (alapértelmezett: 512 bájt, javasolt tartomány: 512–1024 bájt). A hosszabb JSON üzenetek vagy topicok esetén szükség lehet a növelésére.
  • CA Tanúsítvány (CA Certificate): Saját CA gyökértanúsítvány PEM formátumban: text -----BEGIN CERTIFICATE----- ... -----END CERTIFICATE-----
