File Storage Module¶

The File storage module manages the onboard non-volatile SPIFFS/LittleFS flash filesystem. It allows storing audio files (e.g. doorbells, ringtones, alerts), downloading files remotely over HTTP, deleting files, and querying the file index via MQTT.

Operating Behavior¶

  • Storage Capacity: Flash storage space is limited (typically 8MB, depending on the hardware partition table).
  • Safe Upload Check: If an incoming download exceeds available free flash storage space, the module immediately aborts the download and prevents storage overflow.
  • Common Topic Support: In addition to the unique <topic>/command/fs, the module subscribes to the configurable common base topic (<common_topic>/command/fs), allowing one command to upload or manage files across multiple nodes simultaneously.

MQTT Interface¶

Subscriptions (Commands)¶

  • Topic: <topic>/command/fs and <common_topic>/command/fs

Commands are sent as JSON payloads.

1. Upload File from Remote URL¶

  • action: "upload"
  • url: HTTP source URL on the local network or internet.
  • target: Destination file path on internal flash (e.g. "/doorbell.wav").

Example Payload:

{
  "action": "upload",
  "url": "http://192.168.1.100/sound.wav",
  "target": "/doorbell.wav"
}

2. Delete File¶

  • action: "delete"
  • target: Path of the file to remove from flash.

Example Payload:

{
  "action": "delete",
  "target": "/doorbell.wav"
}

3. List Stored Files¶

  • action: "list"

Example Payload:

{
  "action": "list"
}

Publications¶

Dedicated Status Topic

The File storage module state is not included in the central <topic>/status message aggregated by the General module. File storage status is published exclusively on the dedicated <topic>/status/fs topic during/after actions, or when requested by a list command.

  • Topic: <topic>/status/fs

JSON Fields:¶

  • state: Current filesystem activity:
    • RUNNING: An action (e.g. file download) is in progress. New actions are locked until completion.
    • IDLE: The filesystem engine is idle and ready for new requests.
  • lastAction: The action currently or most recently executed (upload, delete, list).
  • lastResult: Execution result of the last action:
    • SUCCESS: Action completed successfully.
    • ERROR: Action failed (e.g. download failed, insufficient space).
    • "": Empty string while state is RUNNING.
  • remaining: Remaining bytes to download during an active upload (0 when idle).
  • files: Array of files on flash storage with filename and size in bytes.

Example Payload during upload:

{
  "state": "RUNNING",
  "lastAction": "upload",
  "lastResult": "",
  "remaining": 2883800
}

Example Payload upon completion or list request:

{
  "state": "IDLE",
  "lastAction": "upload",
  "lastResult": "SUCCESS",
  "remaining": 0,
  "files": [
    {
      "name": "doorbell.wav",
      "size": 2883800
    }
  ]
}
