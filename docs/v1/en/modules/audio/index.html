Audio Module¶

The Audio module provides playback capabilities for WAV audio streams and files on the device (via I2S DAC / amplifier).

Key Features¶

  • Supported Audio Format: Currently, only WAV format is supported, with standard 44-byte PCM headers.
  • 10 Independent Audio Sinks (0–9):
    • Each sink has an independently configurable volume (0–100).
    • Priority Interruption: Playback on a lower-indexed sink interrupts any active playback on higher-indexed sinks (e.g., sink 0 preempts sinks 1–9).
  • Playback Sources:
    • Flash Storage: Playback from internal flash storage (typical capacity is 8MB; requires the File storage module).
    • Network URL (HTTP Stream): Direct streaming and playback from a local or remote HTTP URL.
  • Buffering & Prebuffer:
    • Playback utilizes dedicated memory buffering (typically 4MB PSRAM).
    • Audio output only begins once the buffer fills to a pre-configured threshold (prebuffer size). This threshold can be configured separately in settings for network streams and local files.
  • Scheduled Playback: Playback can be scheduled to begin at a specific future timestamp using the startAt parameter. This must fall between current device time and now + 15 seconds (in epoch milliseconds).

Volume Adjustment Notice

Frequent adjustments and writes to sink volume levels are not recommended due to limited flash write cycles (premature flash memory wear).

MQTT Interface¶

Subscriptions (Commands)¶

Unique and Common Topic Support

All command topics listed below subscribe to both the device-specific base topic (<topic>/command/...) and the configurable shared common topic (<common_topic>/command/...). This allows simultaneous playback, group stopping, or mass volume changes across multiple audio player nodes at once.

1. Stop Playback¶

  • Topic: <topic>/command/audio
  • Payload: raw string: stop

2. Play Local File¶

  • Topic: <topic>/command/playFile
  • JSON Fields:
    • path (string, required): File path in flash storage (e.g. "/doorbell.wav").
    • sink (number, required): Target sink index (0–9).
    • startAt (number, optional): Playback start timestamp in epoch millis (now to now + 15s).

Example immediate playback:

{"path": "/doorbell.wav", "sink": 0}

Example scheduled playback:

{"path": "/doorbell.wav", "sink": 0, "startAt": 1791922925635}

3. Play Remote URL Stream¶

  • Topic: <topic>/command/playHost
  • JSON Fields:
    • url (string, required): HTTP URL of the audio stream/file on LAN or internet.
    • sink (number, required): Target sink index (0–9).
    • startAt (number, optional): Playback start timestamp in epoch millis (now to now + 15s).

Example immediate stream:

{"url": "http://192.168.1.100/doorbell.wav", "sink": 0}

Example scheduled stream:

{"url": "http://192.168.1.100/doorbell.wav", "sink": 0, "startAt": 1791922925635}

4. Set Volume¶

  • Topic: <topic>/command/volume/<sink>
    • sink: Target sink index (0–9)
  • Payload: Volume integer between 0 and 100.

Publications¶

State Changes (Status)¶

  • Topic: <topic>/status

Published on playback state transitions:

  • audio.volume: Array of 10 integers representing volumes of sinks 0–9 (0–100).
  • audio.playState: Player engine state
    • REQUEST_START
    • STARTING
    • PREBUFFER
    • WAITING
    • RUNNING
    • REQUEST_STOP
    • STOPPING
    • STOPPED
    • UNKNOWN
  • audio.downloadState: Stream downloader / file reader state:
    • REQUEST_START
    • STARTING
    • RUNNING
    • REQUEST_STOP
    • STOPPING
    • STOPPED
    • UNKNOWN
  • audio.bufferUsed: Current buffer memory utilization in bytes (0 to 4MB, depends on hardware).

Example Payload:

{
  "audio": {
    "volume": [5, 5, 18, 5, 5, 3, 5, 5, 5, 1],
    "playState": "RUNNING",
    "downloadState": "STOPPED",
    "bufferUsed": 2715820
  }
}

Telemetry¶

  • Topic: <topic>/telemetry
  • audio_buf_errors: Number of critical buffer read/underrun errors that caused playback to abort.

Example Payload:

{
  "audio_buf_errors": 0
}

Settings¶

Configurable buffering parameters in the web portal:

  • File start buffer (bytes): Playback begins after reading and filling the buffer with this amount of data when playing local WAV files from flash storage.
    • Recommended value: 16 kB (16384 bytes).
  • Network start buffer (bytes): Playback begins after downloading and filling the buffer with this amount of data when streaming from a remote HTTP URL.
    • Recommended value: 16–256 kB (depending on Wi-Fi channel noise and latency). Increase this value if audio playback starts with stuttering or initial pops.
