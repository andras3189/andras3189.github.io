Time Module¶

The Time module maintains synchronized system wall-clock time by querying Network Time Protocol (NTP) servers. Accurate real-time clock synchronization is essential for scheduled automations and multi-room audio synchronization.

MQTT Interface¶

Publications¶

  • Topic: <topic>/status
  • JSON Fields:
    • system.unixTimestamp: Current Unix epoch timestamp in seconds.
    • system.timeZoneOffset: Timezone offset relative to UTC in seconds (e.g. 7200 for UTC+2).

Example Payload:

{
  "system": {
    "unixTimestamp": 1792009053,
    "timeZoneOffset": 7200
  }
}

Settings¶

Configurable parameters in the web portal:

  • NTP Servers: Up to 3 NTP servers can be configured (by IP address or domain name).
    • Recommendation: It is strongly recommended to set a local network NTP server as the primary (first) server to minimize network latency.
  • Timezone: Standard POSIX TZ string format (for example, Central European Time: CET-1CEST,M3.5.0,M10.5.0/3).
  • NTP sync interval (minutes): Frequency of time synchronization queries to the NTP servers in minutes.
    • Default: 15 minutes.
    • For audio playback nodes, 15 minutes is recommended to maintain tight sync for timed start events.
    • For pure sensor nodes, buttons, or controllers, 180 minutes is typically sufficient.
